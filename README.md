# Люмен

Telegram-співрозмовник і помічник для груп: природні звернення, окрема пам’ять кожної групи, контекст тем, ігри, нативні опитування, нотатки й нагадування.

**Версія 1.2.0 · 26 жовтня 2026.** Вибрана власником модель — **GPT-6.1-Sol**. У цьому релізі немає автоматичного перемикання на іншу модель. Підключення ChatGPT вже збережене на постійному диску Render. Подробиці нового режиму й перевірок — [RELEASE_1_2.md](docs/RELEASE_1_2.md); попередня контрольна точка й погоджені витрати — [RELEASE_1_1.md](docs/RELEASE_1_1.md).

## Що потрібно зробити власнику

Поточний вхід у ChatGPT і вибір моделі вже завершені. Повторно переносити сесію не потрібно.

1. Один раз відкрити особисте посилання активації Люмена зі свого Telegram й натиснути **Start**. Посилання видає майстер або адміністратор поточної інсталяції; не публікуйте його.
2. Натиснути **«Додати Люмена в нашу групу»**. Надалі додавання бота вже підтвердженим власником також підключає групу автоматично. Випадкові чужі групи не використовують вашу підписку без вашого підключення.
3. Написати: **«Люмен, привіт! Познайоммося»**. Бот сам представиться; команди не обов’язкові. Допоміжний інтерфейс він підбере за потреби.

Пам’ять нової підключеної групи ввімкнена відразу. Люмен вітає групу та пояснює запис і передачу контексту OpenAI. Будь-який учасник може призупинити пам’ять; поновити або очистити всю пам’ять може власник підключення чи адміністратор групи. Для читання фонових повідомлень потрібен вимкнений Privacy Mode у BotFather або права адміністратора бота. Telegram не віддає боту історію до його додавання.

Повторно переносити підключення ChatGPT не потрібно; Termux можна закрити. Для нової інсталяції є [окрема інструкція](docs/CONNECT_CHATGPT.md). Нові платні дії потребують попереднього повідомлення про суму й підтвердження власника.

## Як поводиться Люмен

Теплий, кмітливий, спокійно іронічний. Має власну думку, природно говорить українською, однаково уважно ставиться до всіх учасників. У суперечках відділяє сказане від припущень. Не отримує прихованого профілю власника, інших чатів, біографії, історії чи пам’яті ChatGPT.

Початкова особистість описана в `src/personality.ts`. Власник змінює її через `/character текст`, скасовує останню зміну через `/character undo`, повертає базовий варіант через `/character reset`. Збережені налаштування не дають нових повноважень і не скасовують ізоляцію.

Звернення на ім’я працює в будь-якій частині фрази: «А як думаєш, Люмен?», «Люмене, допоможи», точна `@згадка`, відповідь на його повідомлення або кнопка. Коли учасники говорять між собою, Люмен зберігає доступний текст і мовчить. Самостійні соціальні репліки вимкнені. На звернення може сам запропонувати наступний крок, допомогу, гру чи опитування. Звичайна відповідь не має постійного меню. За контекстом обирає текст, нативне опитування або вікторину, тимчасові варіанти відповіді, реакцію, стікер і форматування.

У форумних групах повідомлення, нотатки, нагадування та ігри мають ID теми. Відповідь і нагадування надходять у початкову тему. Він може згадати домовленості з інших тем тієї самої групи. Назви тем дізнається з отриманих подій Telegram; переліку всіх учасників і давніх тем API не надає. Хід у грі надсилайте відповіддю на ігрове повідомлення або зі зверненням — стороння репліка не стає ходом.

Кожен обирає власну докладність: `/style short|balanced|detailed`, `/style reset`; гумор — `/humor off|light`. Стиль зберігається окремо для цієї людини в цій групі. В інших групах він свій. Явне «Люмен, відтепер відповідай мені коротко» також може зберегти особистий стиль після підтвердження програми. Разове прохання впливає лише на поточну відповідь. Налаштування переживають перезапуск та очищаються під час повного забування.

«Люмен, призупини пам’ять», «Люмен, понови пам’ять», «Люмен, очисти всю пам’ять» працюють без команд. Поновлення й повне очищення перевіряють права через Telegram. Старі `/mode social|host` не вмикають фонові репліки в новому груповому режимі.

## Що можна написати

- «Люмен, запам’ятай: на вихідних хочемо прогулянку біля води».
- «Люмен, що ми говорили про прогулянку?»
- «Люмен, нагадай завтра о 20:00 вибрати фільм».
- «Люмен, давай кооперативний детектив».
- «Люмен, створи опитування: куди їдемо — Львів, Одеса чи Карпати?»
- «Люмен, вивчи гру “Одне слово”: по черзі додаємо по слову, через 20 ходів читаємо спільну історію».
- «Люмен, навчися навички “Наш вечір”: запитай кожного про одну добру подію дня, потім запропонуй спільну активність».
- «Люмен, використай навичку “Наш вечір”».
- «Люмен, допоможи порівняти наші аргументи без здогадок про мотиви».

Фактичне збереження та створення нагадувань підтверджує програма після транзакції. Повідомлення не виконує довільний код на сервері.

## Подача відповіді в Telegram

Основний формат — жива текстова розмова. Модель може виділити ключову думку, оформити цитату, спойлер, посилання чи точний шаблон; програма сама обчислює UTF-16 offsets Telegram entities і коректно ділить довгий текст. У відповідях немає сирих HTML-тегів або обов’язкових меню.

Емодзі використовуються помірно. Не більше одного стікера або реакції за відповідь; між такими прикрасами діє пауза 5 хвилин, якщо їх прямо не попросили. Серйозні теми та особисте «без гумору» приглушують прикраси. Реакція стосується лише поточного повідомлення. Платні ефекти, Premium-емодзі й платні реакції не вмикаються.

Початковий репертуар стікерів — невелика вибірка з публічного Telegram-набору Duck. Доступні звичайні, анімовані та відеостікери, які підтримує Telegram. Стікери, отримані від учасників, запам’ятовуються лише в цій групі. Модель обирає з її перевіреного каталогу; довільні URL і вигадані file_id не виконуються. Якщо каталог недоступний, текстова відповідь працює далі.

Для вікторини можна створити нативне питання з варіантами, автоматичною перевіркою й поясненням Telegram; відкриті текстові партії лишаються доступними. Якщо потрібен короткий вибір, Люмен може показати 2–4 доречні варіанти. Натискання означає саме видимий текст і продовжує діалог; ці варіанти не діють в іншій темі/групі та скасовуються паузою чи очищенням. Уточнення часу або деталей не вимагає повторення всього прохання; воно прив’язане до автора й теми та діє до 30 хвилин.

## Ігри

| Запуск | Реальна механіка |
|---|---|
| `/game quiz` | П’ять раундів із вбудованого банку, кожен відповідає один раз, по балу за правильну відповідь |
| `/game detective` | Два вбудовані сюжети, послідовні підказки, п’ять спільних спроб |
| `/game twenty` | Предмети й істоти з перевіреними ознаками; до 20 запитань, незрозуміла ознака не витрачає спробу |
| `/game story` | 12 почергових текстових ходів, фінальна спільна історія |
| `/game debate` | По два аргументи кожному, рівна кількість ходів, подальше порівняння можна попросити у моделі |
| `/game назва` | Збережені правила вашої гри та почергові текстові ходи |

`/stopgame` завершує партію в поточній темі. У різних темах можуть тривати окремі партії. Базові ігри підтримують від 1 до 20 відомих гравців, «Аргументи» — двох. Вбудовані ігри починаються без прихованих ролей для учасників; відправлення таємних підказок через приватні групові повідомлення не реалізоване.

Нова гра з чату **зберігається як версійовані правила й текстовий сценарій**. Поточний універсальний рушій підтримує чергування та до 20 текстових ходів. Для довільного нового підрахунку, дошки, карт чи прихованих ролей потрібно додати програмний модуль. Люмен про цю межу повідомляє під час запуску такої гри. Навичка — це збережена текстова процедура на його наявних можливостях, а не самовстановлення стороннього ПЗ.

## Пам’ять та приватність

- Кожна підключена група має окрему PostgreSQL-схему. Усі запити її рушія працюють у власному transaction-local `search_path` без fallback до `public`. Відсутня таблиця спричиняє помилку, а не читання даних іншої групи.
- Контекст, пошук, підсумки, нотатки, стилі, ігри й черги не спільні між групами. Приватний чат призначений лише для підключення; групова пам’ять у ньому не показується. Дані профілю й історія власника ChatGPT не імпортуються.
- Повні отримані текстові повідомлення мають автора, Telegram ID, час та ID теми. Для кожної відповіді передаються недавня розмова й окремі порції нотаток, правил, навичок і підсумків.
- Після 60 нових користувацьких повідомлень може створюватися допоміжний підсумок із посиланнями на їхні ID. Оригінали зберігаються. Висновок моделі не вважається перевіреним фактом.
- Пошук старих розмов використовує повнотекстовий індекс PostgreSQL. Це не семантичний векторний пошук; для українських словоформ іноді потрібне інше ключове слово.
- `/memory` і `/notes` показують останні явні нотатки з автором і датою. `/rules`, `/skills`, `/reminders` показують збережені об’єкти.
- `/pause` або явне прохання призупинити запам’ятовування зупиняє збереження, обробку нових реплік і нагадування. Незавершені черги прибираються. Для поновлення потрібен власник підключення або адміністратор групи: кнопка, `/consent` чи «Люмен, понови пам’ять».
- `/forget фрагмент` видаляє оригінальні повідомлення з **точним фрагментом**. Для уникнення збережених переказів також очищає всі похідні відповіді, нотатки, правила, навички, ігри й нагадування. Інші оригінальні повідомлення залишаються.
- `/forget_all` очищає всю активну історію та похідні дані. Прив’язка групи та службовий доступ зберігаються; інші групи не зачіпаються. Копії повідомлень у самому Telegram, вже відправлені провайдеру запити та старі резервні копії мають окремий життєвий цикл.
- Звичайне видалення повідомлення у Telegram не сповіщає цього бота. Потрібна `/forget` або `/forget_all`.
- Редагування отриманого тексту замінює оригінал і для безпеки очищає похідні нотатки, навички, підсумки, правила, гру й невідправлені відповіді. Також прибираються активні нагадування, щоб старий текст не залишився в їхній назві.
- Журнал застосунку містить службові коди, а не тексти розмов чи токени. Конфігурація й OAuth-дані записуються атомарно з Unix-правами `0600`.

Початкова пам’ять порожня. Обробка повідомлень відбувається на сервері бота та в OpenAI. Авторизаційні дані не включаються в контекст персонажа. За вашим явним підтвердженням використано оригінального мишонка Люмена: анімований Telegram-аватар, оформлення майстра та реакції привітання й завершення гри. Перенесені лише візуальні матеріали; біографія й пам’ять ChatGPT не імпортувалися.

## Підписка, моделі та медіа

Основний шлях — офіційний **Sign in with ChatGPT** для власної інсталяції. Доступність залежить від акаунта, тарифу та дозволу під час входу. Успіх реєстрації не підміняється припущенням: майстер вимагає реальну завершену відповідь моделі.

Список моделей отримується з акаунта. Обираєте конкретну модель, автоматичної підміни на дешевшу немає. Ліміти підписки спільні з іншим її використанням. Якщо доступ закінчився чи відкликаний, бот повідомляє про це. **Платний API автоматично не вмикається**.

API-ключ потрібен лише для явно вибраного окремого API-режиму або додаткових медіамодулів. У майстрі можна вказати підтримувані вашим API-акаунтом моделі розпізнавання голосу й генерації зображень. Ці операції оплачуються окремо. Без них Люмен пояснить, що модуль не підключений.

Фото передається сумісній моделі як зображення. Документи з правилами наразі приймаються як текст, `.txt`, `.md` та `.csv`; PDF/Word-розбір у цю версію не входить. Пошук в інтернеті окремо вмикається в майстрі та залежить від дозволів акаунта й моделі. Перегляд довільних URL і запуск стороннього коду відсутні.

Локальний захист від надмірного використання — 200 основних звернень/підсумків на групу на добу за UTC і 5 зображень на групу на рухомі 24 години. Повторний запит під час мережевого збою теж може витратити використання підписки. Це внутрішні обмеження, а не опис тарифу OpenAI.

## Надійність

PostgreSQL зберігає отримані повідомлення до підтвердження Telegram offset. Повторний update не створює повторної нотатки чи ходу. Зміни стану й черга відповіді комітяться разом. Нагадування й партії переживають перезапуск. Успіх відповіді моделі приймається лише після `response.completed`.

Telegram не надає ключа ідемпотентності для `sendMessage`. Якщо мережа обірвалася після можливого відправлення, доставка позначається `uncertain`; автоматичного повтору немає. Власник бачить ID через `/status` і може явно повторити `/retry ID`, усвідомлюючи можливість дубля. Під час перезапуску незавершене відправлення також стає `uncertain`.

Один екземпляр бота захищений PostgreSQL advisory lock. Після втрати з’єднання з цим блокуванням процес завершується. Два сервери не повинні одночасно використовувати одну копію renewable OAuth session.

Запити, вже передані Telegram/OpenAI, не можна гарантовано відкликати паузою. Результат запізнілого виклику не повертається в стерту пам’ять. Telegram тримає недоставлені оновлення максимум 24 години; після тривалого збою можливий пропуск розмови.

У варіанті Docker Compose резервна копія PostgreSQL створюється кожні 6 годин; старі копії прибираються після приблизно 7 днів. Це локальні копії на тому самому сервері, а не захист від повної втрати диска. На Render цей Compose-контейнер не працює: резервування й відновлення керованої бази перевіряються окремо, шестигодинний графік для неї не заявляється. Окреме зашифроване зовнішнє резервування потребує вашого сховища. Докладніше — `docs/OPERATIONS.md`.

## Розробка без Docker

Потрібні Node.js 24+ і PostgreSQL. Встановлення залежностей: `npm ci`. Збирання: `npm run build`. Майстер: `npm run setup`. За локального PostgreSQL задайте власний `DATABASE_URL`; типовий Docker-хост бази — `db`.

Окремі команди: `npm run login`, `npm run models`, `npm run probe`, `npm run doctor`, `npm run smoke`, `npm run profile`, `npm start`. `smoke` перевіряє зовнішні підключення, але не надсилає повідомлень і не читає Telegram update-чергу; справжній діалог у групі перевіряється окремо. `profile` застосовує нову анімацію лише до @lumen_family_agent. Доступні середовищні змінні перелічені в `.env.example`; непорожні значення мають пріоритет над локальним конфігом.

Перевірки: `npm test`. SQL інтеграційно виконується справжнім PostgreSQL-рушієм у PGlite/WASM. Це не заміна перевірки саме вашого Docker-хоста та реальних зовнішніх підключень.
