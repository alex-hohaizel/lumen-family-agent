# Люмен

Приватний Telegram-співрозмовник для двох людей. Власний стійкий характер, спільна пам’ять із нуля, нотатки, нагадування, п’ять ігор, збереження нових правил і текстових навичок.

**Версія 1.1.0 · стан на 26 жовтня 2026:** 93 автоматичні перевірки пройдені. Оригінальний мишонок підготовлений як аватар 800×800 і реакції 512×512 у 60 кадрів/с. Додано окремі налаштування стилю кожного учасника й адаптивну частоту самостійної участі. Render і GitHub доступні через підключення, Blueprint перевірено поточною офіційною JSON Schema. Код розміщено у приватному репозиторії `alex-hohaizel/lumen-family-agent`. Постійний процес ще не розгорнутий; у поточному середовищі немає Telegram-токена чи ChatGPT-сесії. Попередня версія повідомляла про встановлений базовий аватар; нову анімацію в Telegram ще не застосовано. Секретів чи особистої історії в цьому пакеті немає. Деталі: [docs/RELEASE_1_1.md](docs/RELEASE_1_1.md).

## Що потрібно зробити власнику

1. Використати вже створеного [@lumen_family_agent](https://t.me/lumen_family_agent). Його токен береться у [@BotFather](https://t.me/BotFather) та вводиться через майстер або Render Secret; у цей архів токен не включено.
2. Там само: `/setprivacy` → ваш бот → **Disable**. Якщо він уже доданий у групу, видалити й додати знову. Адміністраторські права не потрібні.
3. На комп’ютері з Docker запустити `./start.sh`. Відкрити повне **локальне** посилання з термінала. Майстер приймає Telegram-токен, відкриває **Continue with ChatGPT**, отримує реальний список доступних моделей і перевіряє першу відповідь. Токен не слід надсилати у спільну групу.
4. Натиснути «Підготувати підключення групи», скопіювати одноразову `/bind …`, завершити майстер. `start.sh` запустить базу, бота й резервне копіювання.
5. Через посилання з майстра додати бота до приватної групи **ви двоє + Люмен**. Надіслати `/bind …`. Потім **кожен** учасник пише `/consent`.

Розмови зберігаються й передаються моделі тільки після двох згод. Команда прив’язки не потрапляє в пам’ять персонажа.

Комп’ютер має залишатися ввімкненим для постійної роботи. Рекомендований остаточний запуск — на вашому Linux-сервері з Docker. За налаштованого SSH код і захищене підключення переносить `./scripts/deploy.sh user@server`. Скрипт призначений для **першої** інсталяції на сервері, зупиняє локального бота та зберігає окремий ідентифікатор віддаленого хоста. Інструкція: [docs/OPERATIONS.md](docs/OPERATIONS.md).

У разі роботи лише з телефона потрібен окремий спосіб пройти локальну авторизацію або допомога з комп’ютера. Ця версія не обіцяє однонатискальний вхід у підписку з будь-якого телефона.

## Як поводиться Люмен

Теплий, кмітливий, спокійно іронічний. Має власну думку, природно говорить українською, однаково уважно ставиться до обох. У суперечках відділяє сказане від припущень. Не отримує прихованого профілю власника, інших чатів, біографії, історії чи пам’яті ChatGPT.

Початкова особистість описана в `src/personality.ts`. Власник змінює її через `/character текст`, скасовує останню зміну через `/character undo`, повертає базовий варіант через `/character reset`. Збережені налаштування не дають нових повноважень і не скасовують ізоляцію.

Звичайне звернення: **«Люмен, …»**, `@username` або відповідь на його повідомлення. У режимі `social` він зрідка долучається до розмови двох поза тихими годинами: за швидкого темпу — після 16 реплік і паузи від 20 хвилин, за спокійного — після 10 реплік за кілька хвилин і паузи від 30 хвилин. Складні теми з явними ознаками сварки чи важкої ситуації приглушують самостійну ініціативу. Це приблизні мовні сигнали, не розпізнавання емоцій. Модель може промовчати; після такого рішення також діє пауза. У грі ходи обробляються без згадки імені.

Кожен обирає власну докладність: `/style short|balanced|detailed`, `/style reset`; гумор — `/humor off|light`. Вони не змінюють стиль другого учасника. Явне «Люмен, відтепер відповідай мені коротко» також може зберегти особистий стиль після підтвердження програми. Разове прохання впливає лише на поточну відповідь. Налаштування переживають перезапуск та очищаються під час повного забування.

| Режим | Поведінка |
|---|---|
| `/mode quiet` | Відповідає на звернення, підтримує поточну гру |
| `/mode social` | Може зрідка долучатися до активної розмови |
| `/mode host` | Для ведення поточної гри; довільні фонові повідомлення вимкнені |

`/quiet 23 9` задає години без самостійної ініціативи за Києвом. Прямі звернення та явно створені нагадування в цей час працюють.

## Що можна написати

- «Люмен, запам’ятай: на вихідних хочемо прогулянку біля води».
- «Люмен, що ми говорили про прогулянку?»
- «Люмен, нагадай завтра о 20:00 вибрати фільм».
- «Люмен, давай кооперативний детектив».
- «Люмен, вивчи гру “Одне слово”: по черзі додаємо по слову, через 20 ходів читаємо спільну історію».
- «Люмен, навчися навички “Наш вечір”: запитай кожного про одну добру подію дня, потім запропонуй спільну активність».
- «Люмен, використай навичку “Наш вечір”».
- «Люмен, допоможи порівняти наші аргументи без здогадок про мотиви».

Фактичне збереження та створення нагадувань підтверджує програма після транзакції. Повідомлення не виконує довільний код на сервері.

## Ігри

| Запуск | Реальна механіка |
|---|---|
| `/game quiz` | П’ять раундів із вбудованого банку, кожен відповідає один раз, по балу за правильну відповідь |
| `/game detective` | Два вбудовані сюжети, послідовні підказки, п’ять спільних спроб |
| `/game twenty` | Предмети й істоти з перевіреними ознаками; до 20 запитань, незрозуміла ознака не витрачає спробу |
| `/game story` | 12 почергових текстових ходів, фінальна спільна історія |
| `/game debate` | По два аргументи кожному, рівна кількість ходів, подальше порівняння можна попросити у моделі |
| `/game назва` | Збережені правила вашої гри та почергові текстові ходи |

`/stopgame` завершує партію. Вбудовані ігри починаються без прихованих ролей для учасників; відправлення таємних підказок через приватні групові повідомлення не реалізоване.

Нова гра з чату **зберігається як версійовані правила й текстовий сценарій**. Поточний універсальний рушій підтримує чергування та до 20 текстових ходів. Для довільного нового підрахунку, дошки, карт чи прихованих ролей потрібно додати програмний модуль. Люмен про цю межу повідомляє під час запуску такої гри. Навичка — це збережена текстова процедура на його наявних можливостях, а не самовстановлення стороннього ПЗ.

## Пам’ять та приватність

- Одна дозволена група й два зареєстровані учасники. Чужі групи, приватне листування й повідомлення третьої людини не зберігаються та не надсилаються моделі.
- Повні отримані текстові повідомлення мають автора, Telegram ID та час. Для кожної відповіді передаються недавня розмова й окремі порції нотаток, правил, навичок і підсумків.
- Після 60 нових користувацьких повідомлень може створюватися допоміжний підсумок із посиланнями на їхні ID. Оригінали зберігаються. Висновок моделі не вважається перевіреним фактом.
- Пошук старих розмов використовує повнотекстовий індекс PostgreSQL. Це не семантичний векторний пошук; для українських словоформ іноді потрібне інше ключове слово.
- `/memory` і `/notes` показують останні явні нотатки з автором і датою. `/rules`, `/skills`, `/reminders` показують збережені об’єкти.
- `/pause` або явне прохання призупинити запам’ятовування зупиняє збереження, обробку нових реплік і нагадування. Незавершені черги прибираються. Для поновлення потрібен `/consent` обох.
- `/forget фрагмент` видаляє оригінальні повідомлення з **точним фрагментом**. Для уникнення збережених переказів також очищає всі похідні відповіді, нотатки, правила, навички, ігри й нагадування. Інші оригінальні повідомлення залишаються.
- `/forget_all` очищає всю активну історію та похідні дані. Прив’язка групи, учасники та службовий доступ зберігаються. Копії повідомлень у самому Telegram, вже відправлені провайдеру запити та старі резервні копії мають окремий життєвий цикл.
- Звичайне видалення повідомлення у Telegram не сповіщає цього бота. Потрібна `/forget` або `/forget_all`.
- Редагування отриманого тексту замінює оригінал і для безпеки очищає похідні нотатки, навички, підсумки, правила, гру й невідправлені відповіді. Також прибираються активні нагадування, щоб старий текст не залишився в їхній назві.
- Журнал застосунку містить службові коди, а не тексти розмов чи токени. Конфігурація й OAuth-дані записуються атомарно з Unix-правами `0600`.

Початкова пам’ять порожня. Обробка повідомлень відбувається на сервері бота та в OpenAI. Авторизаційні дані не включаються в контекст персонажа. За вашим явним підтвердженням використано оригінального мишонка Люмена: анімований Telegram-аватар, оформлення майстра та реакції привітання й завершення гри. Перенесені лише візуальні матеріали; біографія й пам’ять ChatGPT не імпортувалися.

## Підписка, моделі та медіа

Основний шлях — офіційний **Sign in with ChatGPT** для власної інсталяції. Доступність залежить від акаунта, тарифу та дозволу під час входу. Успіх реєстрації не підміняється припущенням: майстер вимагає реальну завершену відповідь моделі.

Список моделей отримується з акаунта. Обираєте конкретну модель, автоматичної підміни на дешевшу немає. Ліміти підписки спільні з іншим її використанням. Якщо доступ закінчився чи відкликаний, бот повідомляє про це. **Платний API автоматично не вмикається**.

API-ключ потрібен лише для явно вибраного окремого API-режиму або додаткових медіамодулів. У майстрі можна вказати підтримувані вашим API-акаунтом моделі розпізнавання голосу й генерації зображень. Ці операції оплачуються окремо. Без них Люмен пояснить, що модуль не підключений.

Фото передається сумісній моделі як зображення. Документи з правилами наразі приймаються як текст, `.txt`, `.md` та `.csv`; PDF/Word-розбір у цю версію не входить. Пошук в інтернеті окремо вмикається в майстрі та залежить від дозволів акаунта й моделі. Перегляд довільних URL і запуск стороннього коду відсутні.

Локальний захист від надмірного використання — 200 основних звернень/підсумків на добу за UTC і 5 зображень на рухомі 24 години. Повторний запит під час мережевого збою теж може витратити використання підписки. Це внутрішні обмеження, а не опис тарифу OpenAI.

## Надійність

PostgreSQL зберігає отримані повідомлення до підтвердження Telegram offset. Повторний update не створює повторної нотатки чи ходу. Зміни стану й черга відповіді комітяться разом. Нагадування й партії переживають перезапуск. Успіх відповіді моделі приймається лише після `response.completed`.

Telegram не надає ключа ідемпотентності для `sendMessage`. Якщо мережа обірвалася після можливого відправлення, доставка позначається `uncertain`; автоматичного повтору немає. Власник бачить ID через `/status` і може явно повторити `/retry ID`, усвідомлюючи можливість дубля. Під час перезапуску незавершене відправлення також стає `uncertain`.

Один екземпляр бота захищений PostgreSQL advisory lock. Після втрати з’єднання з цим блокуванням процес завершується. Два сервери не повинні одночасно використовувати одну копію renewable OAuth session.

Запити, вже передані Telegram/OpenAI, не можна гарантовано відкликати паузою. Результат запізнілого виклику не повертається в стерту пам’ять. Telegram тримає недоставлені оновлення максимум 24 години; після тривалого збою можливий пропуск розмови.

Резервна копія PostgreSQL створюється кожні 6 годин; старі копії прибираються після приблизно 7 днів. Це локальні копії на тому самому сервері, а не захист від повної втрати диска. Окреме зашифроване зовнішнє резервування потребує вашого сховища. Докладніше — `docs/OPERATIONS.md`.

## Розробка без Docker

Потрібні Node.js 24+ і PostgreSQL. Встановлення залежностей: `npm ci`. Збирання: `npm run build`. Майстер: `npm run setup`. За локального PostgreSQL задайте власний `DATABASE_URL`; типовий Docker-хост бази — `db`.

Окремі команди: `npm run login`, `npm run models`, `npm run probe`, `npm run doctor`, `npm run smoke`, `npm run profile`, `npm start`. `smoke` перевіряє зовнішні підключення, але не надсилає повідомлень і не читає Telegram update-чергу; справжній діалог у групі перевіряється окремо. `profile` застосовує нову анімацію лише до @lumen_family_agent. Доступні середовищні змінні перелічені в `.env.example`; непорожні значення мають пріоритет над локальним конфігом.

Перевірки: `npm test`. SQL інтеграційно виконується справжнім PostgreSQL-рушієм у PGlite/WASM. Це не заміна перевірки саме вашого Docker-хоста та реальних зовнішніх підключень.
