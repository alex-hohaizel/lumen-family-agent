# Випуск Люмена

GitHub містить код, конфігурацію, залежності, потрібні тести й готові ресурси. Виробничі джерела наліпок, пробні відео, кадри та результати аудитів зберігаються окремо: [авторський архів 1.13.1](https://chatgpt.com/library?file_id=libfile_eacd327e079c8191ac88bc43375e458a&account_id=personal).

1. Перевірити доступ `git ls-remote origin HEAD`, актуальний `main`, поточний commit Render та відсутність іншого активного релізу. Підключений GitHub-плагін не передає свої облікові дані до Git CLI.
2. Узгодити версію в `package.json`, `package-lock.json` і `src/release.ts`. Записати конкретні зміни в `CHANGELOG.md`.
3. Для виправлення наліпок скопіювати лише погоджені готові WEBM/PNG і звичайний `assets/stickers/manifest.json`. Не генерувати повторно незмінені файли. Звірити 120 ID, сцени, порядок і хеші; оновити затверджений fingerprint у `src/joint-startup.ts` і компактний release fixture.
4. Виконати `npm ci --include=dev` та `npm test`. Основні тести перевіряють готовий набір і функції бота; авторський архів не потрібен. Зберігати результати тестів у тимчасових каталогах.
5. Переглянути `git diff --stat` і `git status --short`. Виключити `sticker-lab`, діагностичні відео, архіви, секрети та дані runtime. Закомітити й передати зміни одним звичайним `git push`. Не дробити файли та не створювати їх через сотні API-викликів.
6. Перевірити віддалений SHA. У чинного worker `srv-dbfl0je7bikc73dvg0qg` auto-deploy вимкнений: запустити один погоджений deploy цього `main` і відстежувати його ID. Render виконує повний `npm test` перед стартом; помилка не є підставою пропустити перевірку.
7. Підтвердити потрібну версію, `sticker_pack_verified` для 120 позицій, `sticker_pack_ready`, потім `lumen_started`. Код запускає чати після повної звірки Telegram. Публікація окремих стікерів відновлюється з наявного checkpoint.
8. Зберегти фактичний запис доставки поза вихідним кодом: commit, deploy ID, результати тестів, звірку Telegram і запуск runtime. Під час продовження читати цей запис та поточний стан сервісу; не запускати готові етапи повторно.

Не змінювати секрети, дані чатів, приватність, модель або голос у релізі виправлень наліпок. Історичні описи в документації описують свій випуск; актуальний стан визначають GitHub, Render і поточний запис доставки.
