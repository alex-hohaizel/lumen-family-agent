# Спільний запуск коду й 120 стікерів Люмена 1.13

Спільний запуск завершено: код 1.13.0 активовано після фінального підтвердження всього оновленого набору зі 120 стікерів. Прапорець обов’язкової перевірки увімкнений на поточному сервісі. [Квитанція запуску](RELEASE_1_13_DELIVERY_2026_10_31.json). Подальші кроки описують порядок повторення такого випуску.

`LUMEN_REQUIRE_VERIFIED_STICKER_PACK=true` вмикає обов’язкову перевірку перед створенням і запуском групових runtime. Без власника набору, з неузгодженими локальними файлами, непідтвердженим надсиланням або помилкою фінального перечитування процес завершує запуск із помилкою. Polling, ingress, групові worker і оголошення релізу до цієї перевірки не запускаються.

Перевіряється затверджений склад 1.13 у точному порядку: SHA256 від `JSON.stringify(assets.map(a => [a.id, a.sha256]))` має дорівнювати `589ce76b16ff3d4fa47ed71fab166dfaa8eb80e962a05ceb2e2aaeb91ce3181a`. Старий набір зі 120 сцен не проходить цю перевірку лише завдяки кількості. Далі `ensureStickerPack` перевіряє фізичні локальні файли, відновлює публікацію з checkpoint і перечитує весь фактичний набір Telegram: 120 позицій, назву, порядок, membership та відповідність file_unique_id локальним SHA256/checkpoint.

Порядок запуску оператором:

1. Дочекатися дозволеної публікації повного коміту з кодом, затвердженим manifest і всіма 120 WEBM та прев’ю. Перевірити фактичний віддалений коміт і фізичні хеші; підготовка лише текстових файлів не є таким комітом. Заблоковану автоматичним контролем публікацію не обходити.
2. Лише після цього налаштувати `LUMEN_REQUIRE_VERIFIED_STICKER_PACK=true` для узгодженого сервісу Render і цього повного коміту. У `render.yaml` залишено `false` як сумісний стандарт для нових інсталяцій; для поточного релізу його треба явно ввімкнути. Не запускати 1.13 з `false` як обхід спільної вимоги. Значення приймає тільки точні `true` або `false`; помилкове значення не вимикає перевірку мовчки.
3. Запустити лише погоджений спільний деплой. Операції Telegram виконуються послідовно й можуть бути частково завершені під час публікації. Єдиної атомарної API-операції на 120 стікерів немає; код починає працювати лише після успішного фінального `getStickerSet` для всього затвердженого набору.
4. Перевірити успішний `sticker_pack_verified` із `count=120`, `matched_assets=120`, `matched_memberships=120`, потім `sticker_pack_ready` і лише після нього `lumen_started` потрібної версії. Окремо перевірити актуальні стікери й відповідь бота у Telegram. Прийнятий запит деплою або локальні тести не підтверджують живого запуску.

Якщо перевірка не пройшла, не вимикати прапорець і не запускати код окремо. Зберегти checkpoint і помилку, усунути причину та повторювати лише дозволений спільний випуск. Ця перевірка не повертає вже змінений Telegram-набір до старого стану; відновлення публікації продовжується з перевіреного checkpoint.

Коли прапорець відсутній або дорівнює `false`, збережена попередня поведінка першого встановлення: відсутній власник чи недоступний набір не заважає пройти onboarding. Це режим сумісності, а не дозвіл окремого запуску коду цього релізу.
