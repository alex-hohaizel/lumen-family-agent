# Причини відмов і діагностичні коди

Чинний контракт1.13.6: помилка повертає відому причину, конкретний етап і фактичний стан дії. Не підміняти невідомість припущенням про згоду, права або пошкодження даних. Для невідомої причини прямо назвати невідомість. Уже виконані незалежні прохання зберігаються; uncertain зовнішній ефект спершу звіряється.

Людина отримує один непрогнозований код `LM-…` і пропозицію передати його розробникам. Час закодований у коді; приватні actor/chat/action IDs у нього не включаються. Код не є дозволом на читання інциденту чи повторне виконання дії.

`diagnostic_incidents` у namespace чату зберігає exact app version, operation/stage, reason/detail, effect state, source/task/tool/outbox references і bounded структурні факти. Для скасування — також безпечні target references/version/scope та hashes джерела/доказу. Текст повідомлення, аргументи, prompts, credentials, stack і provider bodies сюди не копіюються. Необхідне адресне читання джерела лишається окремою дозволеною операцією.

Запис кінцевої помилки та її outbox-повідомлення атомарні, де вони виконуються однією транзакцією. Помилка інструмента фіксується після rollback його невдалої роботи й передається викликачеві через trusted receipt; зовнішній JSON не може підробити authoritative пояснення. Retry тієї самої логічної спроби отримує той самий код. Новий запит/збій — новий код. TTL30 днів, максимум2000 записів на namespace, edit/forget/pause/erase видаляють відповідні записи. DB/startup failure використовує безпечний JSON-лог з `persisted:false`; не заявляти, що БД його зберегла.

У Codex почати з коду та чинного HEAD/runtime. Підтриманий read-only маршрут із checkout:

```sh
node --env-file-if-exists=.env tools/diagnostics/incident-lookup.mjs --code LM-… --output-dir /tmp/lumen-incident
```

Потрібне вже дозволене DB-підключення. Скрипт не друкує credentials, не читає переписки, не запускає worker/model/provider effects і не змінює дані. За потреби обмежити `--chat-id`. Повернення `found:false` не є відсутністю збою: код міг існувати лише у fallback Render logs, сплинути за TTL або бути видаленим через forget. Тоді шукати точний код у bounded Render logs; не вмикати broad diagnostics і не повторювати effect.

Далі звірити причину/етап, effect state, exact версію, source/target versions і контракти відповідної операції. Збережений код — діагностичне спостереження, не історичне погодження. Відтворити збій на ізольованому вході, перевірити регресію, незалежне QA й exactSHA CI перед дозволеним випуском.
