# Скасування нагадувань і повторюваної роботи

Намір визначається за змістом поточного власного повідомлення. Модель повертає `cancel_reminder`, точний власний фрагмент у `authorization.quote` та ціль/обсяг; спеціальне слово не є передумовою. Сервер звіряє original request, actor/chat/topic/revision/body та незамаскований власний фрагмент. Цитована назва є даними для пошуку, не дорученням. Quote/code/forward не надають повноважень.

Canonical root і version походять із фактично переданого scoped snapshot або результату inspect. Модель не створює права вибраним UUID. Перша побачена версія зберігається в inbox разом із незалежним наміром через replan/retry; запит не переприв’язується до нової однойменної роботи. Власник може явно назвати UUID приватної роботи; сервер прив’язує версію без передачі її приватної мети груповому planner. Пошук розрізняє reminders, standalone schedules, recurring parent і дочірній запуск.

Звичайне shared reminder лишається під попередніми правилами: автор, явно названий перевірений співучасник або адміністратор може зупинити серію. Приватні записи захищені окремо. Старі `shared=false` rows не стають спільними лише за назвою або членством у групі.

Для старої повторюваної group task іншого автора видимість і право зміни різні. Видимість підтверджується точним parent→occurrence→schedule→task→sent group task_status receipt, або зв’язаною незмінною launch/consent операцією. Пошук іншого автора використовує публічну назву, не внутрішню instruction; planner отримує лише компактні public metadata.

Якщо прямого stop права немає, бот називає власника, створює одну картку з requester та потрібними власниками і показує «Зупинити серію», «Поки не вирішив», «Залишити як є». Власне перевірене прохання requester є тільки його відповіддю; інші підтверджують за себе. До згоди серія залишається активною. Автор своєї серії не проходить зайве опитування.

Proposal прив’язаний до immutable commitment spec, root/source/rule hash/version, topic/revision, автора прохання й expiry. Кожен голос має окремий source/envelope hash; перед виконанням перевіряються докази всіх потрібних людей. Просте «так» зараховується лише як власний reply до фактично надісланої поточної картки; цитата чи вигадана model response не є згодою. Кнопка має окремий transport callback proof. Callback знову звіряє актуальних людей і рядки під transaction fence; не запускає LLM continuation. Після згоди зупиняються canonical parent і незапущені children; claimed/uncertain effect не видається за скасований. Decline, source edit/forget, stale version, інший actor/topic, tamper і replay не виконують повторної зміни.

Голос має погоджувати саме обсяг і негайну дію з картки. «Лише найближчий повтор» не підтверджує зупинку всієї серії; «пізніше» не означає зупинку зараз. Зміна обсягу, часу чи умови не виконується як згода на початкову пропозицію: бот зберігає серію й пояснює, що потрібна кнопка поточної дії або уточнення іншого обсягу.

Історична картка planning без launch не надає прав на незалежно створену серію. Для конкретного нічного інциденту дві позитивні відповіді були збережені в такій окремій картці вже після створення series; історичні дозволи автоматично не переписуються. Read-only діагностичні рядки й приватні IDs зберігаються поза Git.

Помилки мають власні пояснення; універсальна відмова про цитату вилучена. Події `reminder_control_failed` містять лише код і односторонній request tag, без текстів, параметрів, chat/actor IDs чи секретів. Скінченні FakeBrain/PGlite regression доводять інтеграцію семантичного результату; фактичне мовне розуміння живою моделлю та людське приймання перевіряються окремо.
