# Супровід Люмена 1.5.0

Поточна інсталяція використовує наявні Render worker `lumen-family-agent`, приватну PostgreSQL і диск `/var/data/lumen`. OAuth ChatGPT уже підключений, вибрана GPT-6.1-Sol. Повторний вхід потрібен лише після відкликання чи втрати сесії. Не запускайте другий екземпляр з тією самою renewable session.

## Підключення груп

Особисте посилання активації видається власнику. Відкрити його зі свого Telegram, натиснути Start, потім додати бота його кнопкою. Після встановлення власника додавання ним бота також підключає групу. Випадкові чужі акаунти не можуть привласнити підписку. Резервна секретна прив’язка збережена для сумісності, але звичайний сценарій її не потребує.

У групі Люмен коротко знайомиться й пояснює запис. Немає вимоги двох учасників або двох команд згоди. Імена дізнається з отриманих подій Telegram. Кожна група має окрему схему бази; теми належать її спільному контексту. Privacy Mode поточного бота вимкнений і перевірений.

## Перевірка

`npm test` перевіряє PostgreSQL-логіку, ізоляцію та контрольовані зовнішні взаємодії. `npm run doctor` перевіряє Telegram, каталог моделі й реєстр груп. `npm run smoke` не читає getUpdates і не надсилає повідомлень у групу; може зробити один синтетичний запит моделі. `LUMEN_SMOKE_CHAT_ID` дозволяє перевірити конкретну підключену групу. Справжній діалог перевіряється після додавання: звернення на ім’я, пам’ять, звичайна мовчазна розмова, теми та природна гра.

Внутрішній `/health` worker — діагностичний endpoint, а не керована Render HTTP health check. Для background worker Render їх не надає. Стан polling і нові службові помилки перевіряються окремо.

## Оновлення та відновлення

Auto Deploy і Blueprint Auto Sync вимкнені. Публікуйте перевірений код у main, запускайте один deploy вручну й дочекайтеся Live. Build виконує тести перед видаленням dev-залежностей. Диск вимикає zero-downtime rollout: можливе коротке переривання. Не змінюйте розміри ресурсів або платні налаштування без попередження про суму й підтвердження власника.

Один процес володіє advisory lock. Telegram offset зберігається після приймання update. Незавершена обробка поновлюється після рестарту; неоднозначна відправка позначається uncertain й сама не повторюється. Власник може явно повторити її, усвідомлюючи можливий дубль. Втрата зв’язку з advisory lock завершує процес.

Сесія ChatGPT має права 0600 і зберігається на диску. Існуюча поновлена сесія має пріоритет над імпортованим seed. Не друкуйте токени, секрети або тексти розмов у журнали й не комітьте runtime. Повний відкат застосунку не відкочує базу або диск.

## Пам’ять, пауза й резервування

Учасник може сказати «Люмен, призупини пам’ять». Це зупиняє новий запис, обробку та нагадування, прибирає черги й контекстні варіанти. Власник підключення чи адміністратор поновлює або очищає всю пам’ять звичайними словами. Запити, які вже пішли до провайдера, не можна гарантовано відкликати. Інша група не зачіпається.

Резервна копія PostgreSQL має включати всі схеми груп і транспортний реєстр. Docker Compose створює локальні копії за своїм графіком; цей контейнер не працює на Render, тому його графік не заявляється для керованої бази. Резервні копії й провайдерські копії мають окремий життєвий цикл. Погоджені витрати й обмеження Render зафіксовані в RELEASE_1_1.md.

Новий набір можливостей: RELEASE_1_5.md. Генерація нових зображень вимкнена до погодження окремого API-доступу. Під час запуску після синхронізації стікерів queueReleaseNotice ставить оголошення в чергу підключених груп; стан release_notices захищає від дублювання. Доставку оголошення та готовність стікерів перевіряють окремо після розгортання. Резервні команди й бюджети: ADVANCED.md.


## Доручені задачі та діагностика 1.5

`agent_tasks` зберігає мету й прогрес, `tool_runs` — фактичні результати, `tool_approvals` — прив’язане до автора погодження конкретних аргументів. Після рестарту читання можна повторити; зовнішня дія з невідомим результатом автоматично не повторюється. Кнопки діють 15 хвилин у своїй темі. Прострочення переводить задачу до needs_input.

Пауза скасовує доручення й погодження, припиняє спостереження. Поновлення пам’яті саме не відновлює старі доручення. Очищення видаляє також нові таблиці та секрети цієї групи. Ключ connector-vault.key на постійному диску має режим 0600; резервуйте його разом із базою. Не копіюйте секрети в git чи журнали.

Браузер запускається ліниво з довіреного npm-пакета, до трьох розділених сесій; медіафайли сторінок не завантажуються. Після двох хвилин простою процес закривається. Не підвищуйте розмір інстансу без погодження вартості. JavaScript для обчислень працює у QuickJS WASM без Node, файлів і мережі, з 32 MB пам’яті та секундою виконання.

Один раз для релізу головний процес перевіряє фіксовані публічні сторінки, пошук, браузер і обчислення; використовує чинного менеджера OAuth. Події `runtime_check` показують реальні результати, /ready — версію й перевірки. Жодного другого poller чи окремого процесу для refresh token.
