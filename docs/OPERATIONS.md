# Запуск і догляд за Люменом

## Постійний сервер

Невеликий Linux VPS з Docker Compose, постійним диском та вихідним HTTPS до `api.telegram.org`, `api.openai.com` і `auth.openai.com`. Домен і публічний webhook не потрібні: використовується long polling. Порти PostgreSQL та налаштування не мають бути доступні з інтернету. Модель виконується в OpenAI, GPU на сервері не потрібен.

Telegram-токен перевірено через `getMe`: це @lumen_family_agent. Новий анімований аватар застосовано через `setMyProfilePhoto`, повторне читання профілю підтвердило зміну. Токен зберігається лише у приватному локальному runtime і не входить у репозиторій чи архів. Приватний репозиторій `alex-hohaizel/lumen-family-agent` створено й підключено до Render. Створення worker і PostgreSQL зупинене вимогою Render додати платіжний метод. ChatGPT OAuth-сесія та Docker daemon у цьому середовищі відсутні; постійний процес ще не розгорнуто. Актуальний стан: `RELEASE_1_1.md`.

## Локальний запуск і перенесення

1. Розпакуйте пакет на комп’ютері. Переконайтеся, що Docker запущений.
2. Виконайте `chmod +x start.sh scripts/*.sh`, потім `./start.sh`.
3. У терміналі з’явиться повне `http://127.0.0.1:8787/#…`. Відкрийте саме його на цьому комп’ютері. У fragment міститься одноразовий локальний ключ майстра. Він не є ChatGPT-токеном.
4. Підключіть Telegram-токен. За бажанням задайте свій Telegram ID: його показує `/id` у приватному повідомленні боту, коли процес уже запущений. Якщо ID пропущено, власником стає той, хто виконав секретну команду першої прив’язки.
5. Увійдіть через **Continue with ChatGPT**. Callback слухає `127.0.0.1:1455/auth/callback`; OAuth обов’язково проходить у браузері на цій машині. Виберіть свою підписку/workspace та дозвіл використання моделей.
6. Отримайте моделі, оберіть потрібну, перевірте відповідь. Генерація зображень, розпізнавання голосу та API-режим потребують окремих явних налаштувань.
7. Завершіть майстер, скопіюйте `/bind …`. Після кнопки закриття `start.sh` підніме Docker-сервіси. Додайте бота до групи й виконайте прив’язку та дві згоди.
8. Для VPS із налаштованим SSH виконайте `./scripts/deploy.sh user@server`. Docker має бути встановлений заздалегідь, а SSH-користувач — мати доступ до нього. Скрипт зупинить локального бота, перенесе source і потрібні захищені записи через SSH, створить окремий host ID та запустить сервіси. Якщо локальний контейнер `db` запущений, скрипт також зробить захищений dump і відновить його у свіжій базі сервера перед запуском бота. Тимчасовий dump на сервері лишається у `runtime/migration.dump`, локальний — у випадковому `/tmp/lumen-migration.*.dump`; після перевірки перенесення їх варто видалити, бо вони містять стару історію.

`deploy.sh` відмовиться перезаписувати наявну інсталяцію на сервері. Це захищає чинні паролі, дані та rotating refresh token. Для оновлення коду замінюйте вихідні файли, зберігайте `runtime/`, `backups/` і PostgreSQL volume, після чого запускайте `docker compose up -d --build bot`.

## Перевірка після встановлення

| Перевірка | Очікуваний результат |
|---|---|
| `docker compose ps` | `db`, `bot`, `backups` працюють; `db` і `bot` здорові |
| `docker compose exec bot node dist/src/doctor.js` | Telegram, каталог моделей і база доступні |
| `/status` у групі | Прив’язка, дві згоди, обрана модель, видимість звичайних реплік |
| «Люмен, запам’ятай тестову нотатку» → `/notes` | Нотатка має ID і автора |
| Перезапуск `docker compose restart bot` | Нотатка й гра залишаються |
| `/pause` → повідомлення → `/consent` обох | Повідомлення під час паузи не з’являється в історії |
| «Люмен, нагадай через дві хвилини перевірити зв’язок» | Є фактичне нагадування з точним часом |
| `ls backups` | Після першого успішного pg_dump є файл `lumen-….dump` |

`doctor` перевіряє доступи, але не підміняє пробний діалог: остаточна перевірка моделі — `probe` або звернення у групі.

## Поновлення ChatGPT-підключення

Access token оновлюється автоматично; rotating refresh token зберігається атомарно. Протермінований/відкликаний grant потребує повторного входу. Не копіюйте один refresh token на два одночасно працюючі хости.

Для повторного входу збережіть виданий `client_id` і записи акаунта, пройдіть OAuth локально та перенесіть захищений `accounts.json` через SSH у `runtime/` з вимкненим процесом бота. Host ID віддаленого сервера не замінюйте laptop-ідентифікатором. Можна також використати SSH-тунелі loopback-портів для віддаленого майстра, але callback і browser повинні бути правильно з’єднані.

Помилка `credential_refresh_locked` після аварійного завершення означає, що лишився `runtime/refresh.lock`. Спочатку переконайтеся, що не працює інший процес і refresh не виконується. Приберіть лише цей застарілий lock-файл і повторіть вхід, якщо попередня ротація могла завершитися на сервері OpenAI. Не робіть багато refresh-запитів старим токеном.

Записи акаунтів можна відключити через ChatGPT Settings → відповідний застосунок. `npm run logout` викликає офіційне відкликання renewable session; непідтверджене мережеве відкликання не видається за успіх.

## Доставка та збої

Якщо налаштований сторонній webhook, бот завершиться з кодом `existing_webhook_remove_explicitly`; він не стирає чуже налаштування автоматично. Спочатку свідомо приберіть webhook у попередньому застосунку.

`/status` показує невдалі й невизначені доставки. `/retry ID` доступна власнику тільки для `uncertain` і може спричинити дубль, якщо попередня спроба насправді дійшла. Для помилок конфігурації/API виправте доступ і повторіть саме прохання.

У логах немає текстів чату й секретів. Не додавайте власний debug-лог HTTP headers, повних URL Telegram Bot API, OAuth callback або raw provider errors: вони можуть містити секретні дані.

## Копії й повне очищення

`backups` зберігає PostgreSQL dump кожні 6 годин. Файли з правами власника, але додаткового шифрування ці копії не мають. Захищайте сервер і доступ до диска. Файл `accounts.json` із чинним rotating token не слід відновлювати зі старої резервної копії як актуальний.

`/forget_all` чистить **активну базу**; для повного видалення старих даних власник також має прибрати старі dumps, snapshots провайдера та, за потреби, повідомлення Telegram. Найпростіше дочекатися закінчення приблизно 7-денної ротації локальних dumps; це не видаляє snapshots в іншого провайдера. При негайному очищенні зупиніть backup-сервіс, видаліть лише потрібні `backups/lumen-*.dump`, потім запустіть копіювання заново.

Відновлення dump — адміністративна операція: зупинити `bot` і `backups`, відновити вибраний PostgreSQL dump у `db`, перевірити прив’язку/згоди, потім поновити роботу. Відновлення старої бази поверне стару пам’ять і може повернути вже виконані нагадування. Спочатку перевірте їх; не видавайте таке відновлення за гарантовану одноразову доставку.

## Аватар

За вашим підтвердженням у Telegram встановлено анімований аватар оригінального мишонка Люмена. Файл: `assets/lumen-avatar.mp4` (800×800, H.264/MPEG4). Статичний варіант — `assets/lumen-avatar.jpg`, оригінальне зображення для інтерфейсу — `assets/lumen.png`.

Поточна анімація — ревізія 3: безперервна періодична деформація оригінального `assets/lumen.png`, окрема текстура закритих повік і одна піднята лапка для привітання. Усі п’ять роликів тривають 8 секунд (480 кадрів, 60 кадрів/с), H.264, yuv420p, без звуку. Кадри не перемикаються між різними позами й не проходять через оптичну інтерполяцію. Технічні параметри — `assets/animation-report.json`, перевірка декодування, дублів і стику циклу — `docs/video-qa.json`. Відтворення: `python3 scripts/animate-rig.py --mode avatar`; режими `idle`, `waving`, `happy`, `thinking`. Потрібні FFmpeg та пакети з `scripts/animation-requirements.txt`; на Render вони не потрібні, бо використовуються готові MP4. Старі GIF, atlas v2 і попередні скрипти збережені як вихідні матеріали попередніх ревізій і не використовуються для поточних MP4. Див. `ANIMATION_3.md`.

Під час запуску `ensureAvatar` застосовує MP4 через офіційний `setMyProfilePhoto` та записує хеш після підтвердження Telegram. Незмінна версія повторно не завантажується. Перевіряється точний username @lumen_family_agent. Для ручного повтору — `npm run profile`. У групі бот вітається після двох згод і показує радісну анімацію після завершення гри. Реакції передаються через `sendAnimation` як MP4. Майстер відтворює спокійний стан, має кнопку паузи та враховує системне зменшення анімації.

## Render

Конфігурація `render.yaml` створює один worker і одну приватну PostgreSQL-базу у Frankfurt. Диск worker зберігає OAuth-credentials та host ID. Telegram-токен і модель передаються як секретні налаштування; pairing-код генерує платформа. PostgreSQL недоступний із публічного інтернету.

Код потрібно розмістити у приватному GitHub-репозиторії до застосування Blueprint. Реальне створення платних ресурсів ще не виконане. Підключення ChatGPT має пройти перевірений локальний OAuth, після чого protected accounts.json переноситься на постійний диск; файл і токени не комітяться в Git. На Render не використовується backup-контейнер із Compose: політика резервування перевіряється окремо для керованої бази.
