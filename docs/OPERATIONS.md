# Супровід Люмена

Чинна інсталяція використовує Render worker `lumen-family-agent`, приватну PostgreSQL і диск `/var/data/lumen`. Модель — GPT-6.1-Sol, доступ ChatGPT уже підключений. Повторний вхід потрібний лише після втрати або відкликання сесії. Другий процес із тією самою renewable session не запускати.

## Збірка та перевірки

| Команда | Призначення |
|---|---|
| `npm run build` | Тільки production TypeScript у `dist/src` |
| `npm run build:test` | TypeScript тестів у `.test-build` |
| `npm test` | Повний функціональний набір та перевірки механізму пакування |
| `npm run package:release` | Відтворюваний `.release` із наявної production-компіляції |
| `npm run build:release` | Production-компіляція та `.release` |
| `npm run verify:release` | Інвентар/хеші/залежності та локальні медіаперевірки окремого пакета |
| `npm run verify` | Один повний CI-gate: тести, пакет, його перевірка |
| `npm run doctor` | Telegram, каталог моделі, реєстр груп |
| `npm run smoke` | Явна синтетична перевірка; може звернутися до моделі |
| `npm run diagnostics` | Запуск єдиного worker з 11 широкими живими перевірками |

Операційні команди всередині `.release` працюють із його власними модулями та ресурсами. Потрібний чинний `RUNTIME_DIR`; на Render це абсолютний шлях на постійному диску. Приватні файли не входять у пакет і не копіюються з checkout. Після перевірки автономності finalizer прибирає з native build вихідні тести/прев’ю та зайву кореневу копію залежностей; він не торкається даних runtime/backups і заборонений для локального checkout.

Звичайний запуск не виконує широкі model/web/browser probes. `/ready` показує їхній чесний стан `not_run`; після явного `--diagnostics` — `running`, `verified` або `failed`, окремо від готовності основного worker. Звіт `runtime-diagnostics.json` приватний; старі версійні звіти не зараховуються як перевірка нового запуску. Не запускати живі probes для підтвердження лише зміненого PNG або тексту документації.

## Render

Цільова схема випуску — `After CI Checks Pass`, один повний CI для SHA, потім build `npm ci --include=dev && npm run build:release && node tools/release/finalize-render.mjs`, start `cd .release && npm start`. Звіряти фактичні налаштування сервісу: Blueprint Auto Sync не застосовує файл самостійно. [Повний порядок і відкат](RELEASING.md).

У background worker немає керованої Render HTTP health check. Внутрішні `/health` і `/ready`, polling, lease та службові журнали перевіряються окремо. Через постійний диск можливе коротке переривання під час rollout. Не змінювати платний план, диск або кількість інстансів без окремого доручення.

## Дані, доставка й відновлення

Кожна група має окрему схему БД; private DM, тема, actor і audience зберігають свої межі. Власник підключення та адміністратори мають лише визначені кодом права. Telegram offset зберігається після приймання update. Один процес володіє advisory lock; втрата lease зупиняє його.

Незавершена робота поновлюється після рестарту за своїм контрактом. Невідома зовнішня доставка не повторюється автоматично як нова дія. `queued`, готовий файл і підтверджена доставка — окремі стани. Кнопки та оголошення зберігають dedup/receipt; старі дані й callback-и підтримуються чинним кодом.

Пауза/видалення/відкликання впливають на залежні черги, результати й контекст. Старий backup не може повертати видалене без чинного privacy fence. Резервувати потрібно всі схеми груп, транспортний реєстр і захищені ключі диска. Docker backup-loop стосується лише Compose; його графік не заявляється як графік резервування Render.

Секрети й сесія мають приватні права. Чинна поновлена сесія має пріоритет над імпортованим seed. Не друкувати токени або тексти розмов у журнали й не комітити runtime. Код rollback не відкочує БД або диск.

## Діагностичні інструменти й альтернативний запуск

Ручні інструменти описані в [tools/diagnostics](../tools/diagnostics/README.md). За замовчуванням вони друкують результат, тимчасові файли прибирають. Опційний каталог звітів має бути за межами репозиторію. Model benchmark потребує явного opt-in і не є критерієм якості всіх функцій Люмена.

Docker/Compose — альтернативний спосіб. Пакет будується тією самою процедурою; контейнер повинен пройти окремий CI smoke із nonroot/read-only/tmpfs обмеженнями після змін Docker/пакування. Не переводити поточний Render на Docker заради чистки. Підтримувані тимчасові ресурси визначені в `compose.yaml`; 32 MiB недостатньо для Chromium.
