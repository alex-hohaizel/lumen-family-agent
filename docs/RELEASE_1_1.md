# Люмен 1.1.0 — контрольна точка запуску

26 жовтня 2026 · Europe/Kyiv · цільовий бот @lumen_family_agent.

## Перевірений результат

- Код збирається на Node.js 24.22.1. Повторна перевірка архіву дала 75/75 тестів; після змін — 93/93.
- Підготовлено п’ять MP4 із вихідних кадрів оригінального мишонка: аватар, спокій, привітання, радість, роздуми. 60 кадрів/с; без звуку. Аватар 800×800, реакції 512×512. Пози й вигляд персонажа не перемальовувалися. Міжкадрова інтерполяція покращує плавність, але не додає нової акторської анімації.
- Доставка реакцій переключена на MP4. Установлення профілю перевіряє username й не повторює завантаження незмінного файлу після рестарту.
- Стиль відповіді та гумор зберігаються окремо для кожної людини. Разове прохання не змінює постійний стиль. Тихі години, явні звернення, пауза пам’яті й ізоляція двох учасників збережені.
- Самостійна участь враховує темп, участь обох і явні мовні ознаки складної теми. Після рішення промовчати чи помилки також діє пауза, щоб не викликати модель на кожну репліку.
- Поточна офіційна JSON Schema прийняла `render.yaml`. Build на Render виконує тести до видалення dev-залежностей.
- Read-only перевірка Render показала робочий простір користувача без сервісів. GitHub спочатку не мав репозиторію для цього проекту. Після особистого входу власника створено приватний `alex-hohaizel/lumen-family-agent`; файли розміщено через авторизований браузер. Render і Telegram у браузері потребують окремого входу.

## Що ще не виконано

1. Створення Render worker та PostgreSQL за Blueprint. Обліковий доступ працює, ресурси не створені. Платний план не активований цим сеансом.
2. Передавання Telegram-токена у Render Secret. Вхідний архів спеціально не містить секретів; токен зі старого сеансу тут не відновлений.
3. Особистий Sign in with ChatGPT, вибір моделі з фактичного каталогу та успішний `probe`. Підписку не можна вважати підключеною через сам факт наявності коду OAuth.
4. Установлення нової анімації на живого бота та перевірка реального повідомлення в цільовій групі після прив’язки й двох згод.

## Послідовність продовження

1. Використати створений приватний репозиторій `alex-hohaizel/lumen-family-agent`: джерела та `render.yaml` уже розміщені. Секрети й runtime не комітити.
2. У Render застосувати Blueprint саме цього репозиторію: один worker, один екземпляр, постійний диск credentials і приватна PostgreSQL у Frankfurt. Перед створенням звірити відображену вартість. Сервіс не потребує публічних webhook чи відкритої назовні бази.
3. Додати `TELEGRAM_BOT_TOKEN`, за потреби `OWNER_TELEGRAM_ID`, а після авторизації — фактичний `OPENAI_MODEL` та захищений файл `chatgpt-accounts.json`.
4. Для входу у підписку на власному комп’ютері з Node.js 24+: `npm ci`, `npm run build`, `npm run setup`. Docker для самого входу не потрібен. Відкрити повне локальне посилання й пройти Sign in with ChatGPT. Вибрати модель з каталогу та завершити пробний запит.
5. OAuth callback `http://127.0.0.1:1455/auth/callback` має повертатися на машину браузера й запущеного майстра. Його не замінюють URL Render. Офіційний шлях для власного сервера: пройти вхід локально й перенести тільки захищений `runtime/accounts.json` як Render Secret File з назвою `chatgpt-accounts.json`. Локальний `host.json` не переносити: Render створює власний ID хоста на постійному диску. Паролі, коди входу й токени не публікувати в чаті.
6. Дозволити оновленню сесії належати одному Render-процесу; не запускати одночасно локальний бот із копією тієї самої сесії. Після імпорту новий rotating session на диску має пріоритет над початковим seed.
7. Перевірити deploy до робочого стану та логи `lumen_started`, без `startup_failed`. Помилка профілю логуються окремо; за потреби повторити `npm run profile`.
8. У потрібній приватній групі: додати бота, виконати `/bind` із фактичним pairing-кодом, кожен учасник дає `/consent`. У BotFather має бути вимкнено Privacy Mode для звичайних групових реплік. Права адміністратора боту для цієї реалізації не потрібні.

## Наскрізна перевірка в групі

| Дія | Що має бути видно |
|---|---|
| `/status` | Дві згоди, модель, звичайні повідомлення доступні, немає проблем доставки |
| «Люмен, привіт. Відповідай одним реченням» | Справжня завершена відповідь ChatGPT у цій групі |
| `/mood happy`, `/mood hello`, `/mood thinking` | Три плавні анімовані реакції без службових підписів |
| Перший: `/style short`; другий: `/style detailed` | Окрема докладність у відповідях кожному |
| «Люмен, запам’ятай: перевіряємо запуск»; `/notes` | Нотатка з автором і справжнє підтвердження збереження |
| Явне нагадування на близький конкретний час | Доставка в зазначений момент за Europe/Kyiv |
| `/game story`, по одному ходу кожному | Чергування, збереження стану після одного контрольованого рестарту |
| `/pause`, тестова репліка, `/status` | Новий текст не зберігається та не передається моделі; для поновлення дві згоди |

`npm run smoke` додатково перевіряє токен, відсутність webhook-конфлікту, базу, прив’язку/згоди, доступність моделі й завершену відповідь. Він не читає `getUpdates` і не надсилає групових повідомлень. Поле `live_group_dialogue_verified` лишається `false`: ця команда не підміняє живий діалог.
